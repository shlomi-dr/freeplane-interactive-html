# Validation status

## Companion preview

The standalone companion is version `0.2.0-alpha.1`, local and unpublished. The following checks passed on 2026-11-09 with installed Freeplane 1.13.4, bundled Java 21.0.11, and macOS 26.2. The app requires a graphical Freeplane runtime. Freeplane 1.13.3, Linux, Windows, and other configurations remain unverified.

1. `python3 tests/companion-integration.py --runtime` passed all eight tests. The suite checks invalid paths, aliases of the input file, misleading zero exits, failures after a success marker, quoted/Unicode paths, timeout cleanup, a real map export, literal formula export, and preservation of an existing destination when a straight connector is rejected. The retained run output is `/tmp/companion-integration-results.txt`.
2. The actual runner extracted from the macOS ZIP exported the original fictional example to `/tmp/freeplane-companion-release-preview/Clockwork Garden Festival.html`: 43 nodes, two cubic cross-links, one summary, both sides, 990,037 bytes. The map SHA256 remained `c38f7e0b9909300cfaff6feaf1b56f6899ab84f6f978f7f307ca0ec5bd5e457e`.
3. The wrapper uses a fresh profile, disables formula evaluation and single-instance forwarding, and invokes only its bundled trusted export script via `-R`. The script checks the loaded file identity and marks the map read-only. The wrapper publishes a same-directory staging file only after a zero exit, a fresh success marker, and nonempty output. It does not install a plugin or change global script permissions. This is not a general sandbox for untrusted maps.
4. A separate two-second timeout check against the packaged runner confirmed that the owned native Freeplane PID contained `libjvm.dylib`, exited after termination, and left the old destination unchanged. The result is `/tmp/freeplane-companion-release-preview/timeout-verification.txt`. This verifies the embedded-JVM launch behavior on the tested macOS installation.
5. Both ZIPs built successfully with allowlisted resources and executable permissions. `osacompile` compiled the applet. The builder preserves its generated executable metadata, then ad-hoc signs and verifies the finished bundle; `codesign --verify --deep --strict` also passed on the extracted app. The app is not Developer ID signed or notarized. The CLI ZIP uses fixed entry metadata; the compiled macOS app is not claimed to be byte-reproducible.
6. Finder choose/drop dialogs, the output chooser, and automatic browser opening have not been exercised end-to-end. A screen-control inspection timed out, so that manual app check is left for operator review. The new HTML manifest and SVG capture were checked; browser interaction checks below concern the earlier output, though the viewer template is unchanged. No new recording was made.

The preview is ready for a local trial, not a published release. Publication and the community announcement await operator review.

## Historical prototype and viewer evidence

The following checks concern the former in-process add-on prototype and its checked-in sample HTML, not the standalone companion.

1. The earlier native prototype passed permissive smoke, demo-export, and installation lifecycle checks with Freeplane 1.13.3 and 1.13.4, JetBrains Runtime 21.0.11, and macOS 26.2. Those checks ran in disposable profiles and do not establish companion behavior. A later default-permissions run on Freeplane 1.13.4 failed because renderer reflection requires `ReflectPermission("suppressAccessChecks")`, denied by the default script protection domain. This is why the experimental startup add-on is not recommended.
2. The checked-in `examples/Clockwork Garden Festival.html` was generated from the unmodified fixture by the in-process prototype on Freeplane 1.13.3. Browser interaction checks over local HTTP passed for folding, expand/collapse all, search, pan, zoom, fit, and a reserved `example.com` link. The viewer had 41 visible nodes and two crosslinks; collapsing reduced these to eight nodes and no crosslinks. Those observations describe that sample file only and do not validate new companion output.
3. Earlier prototype capture supported both map sides, native node artwork, single-level summaries, and cubic crosslinks. Straight crosslinks are unsupported. Its custom layout did not reproduce Freeplane's exact layout. Nested summaries, other connector shapes, external linked content, direct `file://` behavior, large-map performance, and broader map features were not established. These are historical implementation observations, not a companion acceptance result.

The prior prototype harness and installation lifecycle results remain in repository history. Do not cite its smoke tests, native installation checks, or sample browser checks as evidence that the companion runner or macOS app works.
